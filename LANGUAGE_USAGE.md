## Method

1. Read the public GitHub language response for each repository, using `GET /repos/{owner}/{repo}/languages`.
2. Exclude the three confirmed reference forks: [UNETR](https://github.com/Ramtin-Mojtahedi/UNETR), [research-contributions](https://github.com/Ramtin-Mojtahedi/research-contributions), and [gazebo_models](https://github.com/Ramtin-Mojtahedi/gazebo_models).
3. Inspect all 13 notebook metadata records in the remaining collection. Every notebook identifies Python through its kernel or language metadata.
4. Count each language once per repository. A repository may appear under multiple languages.

GitHub's detection can omit generated, vendored, or other excluded files. The measures describe detected public project coverage, not time spent, lines personally authored, expertise, proficiency, production readiness, or current activity. They are a dated snapshot, not a live ranking.

GitHub also detects TeX in the portfolio. That material consists of BibTeX citation files, so it is not included as a programming-language proficiency signal.

The additional languages listed in the profile's expandable section come from the existing [portfolio language record](https://github.com/Ramtin-Mojtahedi/Ramtin-Mojtahedi.github.io/blob/main/assets/programming-languages.js); this repository audit does not independently establish proficiency in those languages.
